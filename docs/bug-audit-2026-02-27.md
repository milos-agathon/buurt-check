#### P1-41: downloadPdfBlob Safari iOS failure

**File:** `frontend/src/services/api.ts:353-362`

```typescript
export function downloadPdfBlob(blob: Blob, filename: string): void {
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  URL.revokeObjectURL(url);  // ← Immediate revocation
}
```

`a.click()` triggers an asynchronous download on Safari iOS. The blob URL is revoked before Safari can access the content, resulting in a failed or empty PDF download. This is a [known WebKit issue](https://bugs.webkit.org/show_bug.cgi?id=167341).

**Fix:** Delay revocation: `setTimeout(() => URL.revokeObjectURL(url), 60000)`.

#### P1-42: Violent crime count zero treated as unavailable

**File:** `backend/app/services/tier_b.py:264-268,295`

```python
violent_count = sum(
    value or 0.0
    for code, value in code_to_count.items()
    if code in _CRIME_VIOLENT_KEYS
)
# ...
violent_count=violent_count if violent_count else None,  # 0.0 → None!
```

If all violent crime categories have `0` registered crimes, `sum()` returns `0.0`. The falsy check converts this to `None`, which the frontend interprets as "data unavailable" rather than "zero violent crimes". This gives a misleadingly positive impression by hiding a genuinely safe statistic.

**Fix:** `violent_count=violent_count if violent_count is not None else None` — but since `sum()` never returns `None`, simply pass `violent_count` directly. If distinguishing "no data" from "zero" is needed, check whether any violent keys were present in the CBS response.

#### P2-46: Crime stats sequential request chain

**File:** `backend/app/services/tier_b.py:225-248`

```python
population = await _fetch_population(cleaned_buurt)       # ~500ms
latest_year = await _fetch_latest_period(yearly_base)       # ~500ms
latest_month = await _fetch_latest_period(monthly_base)     # ~500ms
yearly_rows, monthly_rows = await _fetch_crime_rows(...)    # ~500ms × 2
```

5 sequential HTTP requests to CBS, all independent until the period lookups complete. Could be restructured as:

```python
# Phase 1: All independent
population, latest_year, latest_month = await asyncio.gather(
    _fetch_population(cleaned_buurt),
    _fetch_latest_period(yearly_base),
    _fetch_latest_period(monthly_base),
)
# Phase 2: Depends on phase 1
yearly_rows, monthly_rows = await _fetch_crime_rows(...)
```

This reduces ~2.5s to ~1.0s for the crime data portion of the tier-b endpoint.
