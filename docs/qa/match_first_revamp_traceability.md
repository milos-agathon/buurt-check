## Punch-List Fixes 2026-05-13 to 2026-05-14

- Match-return Dossier URLs without `lookup`, such as `#/address/{vbo_id}?match_return=...`, now keep the user in the Dossier route and render a localized address-unavailable shell instead of redirecting to Search.
- The Back to match map action is rendered by the Dossier route wrapper whenever match-return context exists, so it remains available through loading, empty, error, and successful address states.
- Match run `completed` / `running` state is no longer trusted from `localStorage`. Until backend run/status/results endpoints are wired, direct success and results routes render neutral localized shells rather than implying that matching has completed.
- Survey answers are scoped by match session ID, preventing a new session from inheriting stale answers from an earlier one.
- `App.tsx` reuses the shared route parser for structured `match_context`, preserving selected neighborhood, selected house, map center, zoom, and list scroll on cold-start Dossier URLs.
- Direct match neighborhood URLs do not trust persisted Dossier return context from `localStorage`; that context is only reused for the active Dossier back action.
- Failure and unavailable copy now has explicit bilingual keys, enforced by `frontend/src/test/match-i18n.test.ts`, for no strong matches, slow backend, failed backend, completed-with-fallback, no reliable address, no-result states, missing 3D, neutral results placeholders, and Dossier address-unavailable recovery.
- Neutral placeholder copy is used consistently for run, success, results, and neighborhood direct routes until backend matching status/results exist; explicit failed-backend copy is reserved for confirmed failed runs.
- Dossier match-return context now preserves mobile map/list mode plus selected result ID and rank, reducing context loss when returning from a house Dossier to the match map.
- Settings is hidden during match-first onboarding screens so the flow remains one decision per screen.
- Match route transitions respect reduced-motion preferences.
- Failed match progress states now expose a localized retry action that retries the same match session instead of forcing users to restart the survey.
- Direct Phase 1 survey question routes above step 1 are rejected until the final survey question set lands in Phase 2.
- Back-to-match-map context is rehydrated after refresh only when the user has actually activated the Dossier Back to match map action; passive or arbitrary localStorage context still cannot unlock direct neighborhood placeholders.
- Survey review copy now says Housing goal / Woondoel instead of Search type / Zoektype.
- Direct neighborhood placeholder routes are included in the Phase 1 accessibility coverage.
- Invalid Phase 1 match routes now recover back to the active match survey as the focused primary action, with address search kept as a secondary option.
- Restored selected-neighborhood placeholders now use neutral restored-context copy and expose a Back to survey action while preserving route context attributes for later map/detail hydration.
- App-driven route changes no longer suppress the next real hash route, and browser Back/Forward route changes now re-run the Phase 1 hash-route parser.
- Loaded Dossier exits that send users back to search now preserve match-return context so the existing Back to match map path survives the next address selection.

## Current Phase 1 Limits

- The survey is intentionally one dummy question for Phase 1 shell completion. Final 10-12 question content, backend answer persistence, and preference-vector generation remain Phase 2 work.
- The final survey action now routes through the session run step with direct-route recovery guards. Backend async matching completion, real result payload hydration, and server-backed run status remain later phases; completed-looking routes intentionally stay as explicit placeholders until real backend state is available.
- Neighborhood-only 3D building loading is not changed in this phase; no national 3D loading path was introduced.
